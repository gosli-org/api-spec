# Architecture

API Spec defines the shared JSON representation used by a TypeScript client and Go server. For installation, consumer examples and development commands, use the [README](README.md).

## Source and generation

[`src/main.tsp`](src/main.tsp) is the source of truth. Models belong to the `ApiSpec` service namespace. The current contract contains `Client.Request` with required fields `id` (string), `type` (`Client.RequestType`) and `token` (string); HTTP operations are not yet defined.

Generation follows this pipeline:

```text
src/main.tsp → openapi/openapi.yaml → TypeScript/index.d.ts
                                  → Go/api.gen.go
```

[`tspconfig.yaml`](tspconfig.yaml) configures TypeSpec to emit OpenAPI 3.0. `openapi-typescript` derives TypeScript declarations from OpenAPI. `oapi-codegen` derives Go models in package `apispec`, configured by [`oapi-codegen.yaml`](oapi-codegen.yaml).

Models are emitted even before HTTP operations reference them: TypeSpec retains unreachable types and the Go generator skips pruning. Both language models derive from the same OpenAPI document.

Generated artifacts are versioned so consumers can use the package without running generators. Generator versions are pinned by [`package-lock.json`](package-lock.json), [`go.mod`](go.mod) and [`go.sum`](go.sum).

## JSON contract

Request IDs are generated by the sender and carried as strings. A UUID string is suitable, but the model imposes no format or uniqueness validation. Keeping the ID as a string avoids runtime dependencies in the generated Go models.

`Client.RequestType` has three values: `listProjects`, `createSession` and `attachSession`. The request currently carries the ID, command type and token; command-specific parameters are not yet modeled.

Field names, required/optional fields and nullability are defined in TypeSpec. Go identifiers may differ (`Id` versus `id`); generated JSON tags preserve wire names. Use `@encodedName("application/json", "wire_name")` when the JSON name differs from the TypeSpec property name.

Use strings for integers outside JavaScript's safe integer range. TypeScript types and Go structs describe the representation; runtime validation belongs to consumers, as explained in the [usage examples](README.md#use-in-a-typescript-client).

## Verification

`npm run check` type-checks the generated TypeScript declarations and compiles the Go package. These checks establish that the generated code is valid; they do not validate runtime behavior in consumers.

[`CI`](.github/workflows/check.yml) regenerates artifacts, runs checks and rejects changed or newly generated files missing from the committed output. This keeps generated contracts aligned with their source.
